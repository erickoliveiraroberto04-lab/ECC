# Professional Design Workflow Tools

A curated lookup table of workflow and production tools for running a
design process end-to-end — from client feedback to developer handoff.
Complements the other two design skills, which cover assets and
inspiration; this one covers process.

## When to Use

- Need to check a design's accessibility (contrast, color blindness
  simulation) before delivering it.
- Need to hand off a finished design to a developer with specs/assets.
- Need client feedback/approval on a design before finalizing it.
- Need to see how visitors actually use a live site (analytics/heatmaps).
- Need a prototyping or wireframing tool before building the real thing.
- Need to record a screen or app demo for a client.
- Need a no-code website/logo generator for a very fast turnaround job.
- Need a way to track versions of a design file over time.

## How It Works

### Accessibility Testing

| Tool | Best for |
|------|----------|
| [WAVE](https://wave.webaim.org/) | Free browser-based accessibility evaluation of a live page |
| [Stark](https://getstark.co/) | Color-blindness simulation and contrast checks inside design tools |
| [Colorable](https://colorable.jxnblk.com/) | Quick contrast ratio check between two colors |
| [Axe](https://www.deque.com/axe/) | Automated accessibility testing integrated into dev workflows |

### Design Feedback & Client Proofing

| Tool | Best for |
|------|----------|
| [GoVisually](https://govisually.com/) | Online proofing/approval workflow for client sign-off |
| [Filestage](https://filestage.io/) | Reviewing videos, designs, and documents with clients in one thread |
| [Excalidraw](https://excalidraw.com/) | Free collaborative whiteboard — quick shared sketches with a client live |
| [Miro](https://miro.com/) | Broader visual collaboration board for workshops and feedback sessions |

### Design Handoff (to developers)

| Tool | Best for |
|------|----------|
| [Zeplin](https://zeplin.io/) | Automatic specs, assets, and code snippets from a design file |
| [Avocode](https://avocode.com/) | Inspecting a design's layers/values without owning the design app |
| [Sketch Measure](https://github.com/utom/sketch-measure) | Free, open-source redline annotation plugin for Sketch |

### Design Version Control

| Tool | Best for |
|------|----------|
| [Abstract](https://www.abstract.com/) | Version, branch, and review Sketch/Figma files like code |
| [Kactus](https://kactus.io/) | Free, open-source Git-based version control for Sketch files |

### Live Site Analytics & Feedback

| Tool | Best for |
|------|----------|
| [Google Analytics](https://analytics.google.com/) | Free, standard traffic/behavior tracking — the default starting point |
| [Hotjar](https://www.hotjar.com/) | Heatmaps and session recordings, good for showing a client *why* a redesign helps |
| [Fathom](https://usefathom.com/) | Privacy-friendly analytics without personal data tracking |

### Prototyping

| Tool | Best for |
|------|----------|
| [Figma (prototyping mode)](https://www.figma.com/) | Free-tier, click-through prototypes directly from design files |
| [Marvel App](https://marvelapp.com/) | Fast wireframe-to-prototype for early client sign-off |
| [Origami](https://origami.design/) | Free tool for higher-fidelity interactive prototypes (Mac) |

### Wireframing & Information Architecture

| Tool | Best for |
|------|----------|
| [Octopus.do](https://octopus.do/) | Visual sitemap builder — planning site structure before design |
| [Moqups](https://moqups.com/) | Real-time collaborative wireframes and diagrams |

### No-Code Site & Logo Builders (fast-turnaround jobs)

| Tool | Best for |
|------|----------|
| [Carrd](https://carrd.co/) | Free, fast one-page responsive sites — good for a quick landing page |
| [Logo Makr](https://logomakr.com/) | Free logo assembly from fonts/icons for a rough concept |

### Screen Recording (client demos)

| Tool | Best for |
|------|----------|
| [CleanShot](https://cleanshot.com/) | Polished screen capture with built-in annotation (Mac) |
| [Screen Studio](https://screen.studio/) | Automatic zoom/smooth animation for a professional-looking demo |

### Development/Testing Browsers

| Tool | Best for |
|------|----------|
| [Polypane](https://polypane.rocks/) | Testing a responsive design across many viewport sizes at once |
| [Litmus](https://litmus.com/) | Previewing how an HTML email renders across email clients |

## Examples

- "Preciso mostrar pro cliente que a paleta escolhida é acessível pra
  daltônicos" → Accessibility Testing → Stark or Colorable, screenshot the
  result.
- "Preciso que o cliente aprove o design antes de eu começar a construir" →
  Design Feedback & Client Proofing → GoVisually or a shared Excalidraw
  board.
- "Vou entregar o design pra um desenvolvedor implementar" → Design
  Handoff → Zeplin (generates specs automatically from the file).
- "Cliente quer ver como as pessoas usam o site atual antes do redesign" →
  Live Site Analytics & Feedback → Hotjar (heatmap as visual proof).
- "Preciso de um protótipo clicável rápido antes de codificar de verdade" →
  Prototyping → Figma's own prototyping mode (no extra tool needed if
  already designing there).
- "Cliente pediu um site simples de uma página até amanhã" → No-Code Site
  & Logo Builders → Carrd.

## Anti-Patterns

- **Skipping accessibility checks because "the client didn't ask."**
  Contrast and color-blindness issues are cheap to catch before delivery
  and expensive to explain after a complaint — check by default.
- **Using a no-code builder (Carrd, Logo Makr) as your standard offering.**
  These are for genuine rush jobs or single-page needs — a paying client
  expecting a custom site should get a hand-coded, brand-specific result.
- **Sending raw design files instead of a handoff export.** A developer
  (including yourself, coding the site later) wastes time re-measuring
  spacing and colors that a handoff tool would have generated automatically.
